## 1. 环境与方法

本次使用 Windows、本机原生 `codex-cli 0.159.2`、.NET SDK `8.0.425`，采用 App Server stdio，复用已有的 ChatGPT 登录。未安装额外 CLI、未复制凭据，也未为制造额度消耗额外调用模型。

本机生成 schema 后，核对 `initialize`、`account/read`、`account/rateLimits/read` 的方法和字段，再运行仓库中的独立程序。应用端内置额度工具仅用于核对，不是实现的数据源。

公开记录只保留验证结论，不附账号 email、account ID、令牌、安装中的个人目录、真实原始响应或用户配置。示例数据只使用测试工具中的虚构值。

首次实现将初始化中的 `account/updated` 误判为切换。修正为账号检查后观察版本；额度读取中发生变化则丢弃并有限重试。修正后真实读取通过，测试覆盖这一通知顺序。

## 3. 自动化验证

本次构建无警告、无错误。测试工具执行 14 项场景，全部通过：

1. 多额度桶优先、空比例、未知字段、公开模型脱敏和官方使用权限。
2. 单桶回退、百分比边界、未知窗口和空窗口。
3. 子进程握手与初始化账号通知。
4. 模拟未登录和 API key 认证。
5. 模拟读取期间持续账号变化，拒绝发布混合结果。
6. 模拟账号响应结构变化，返回兼容性错误。
7. 模拟额度通知，重新读取完整数据。
8. 交错响应按 ID 匹配。
9. 超时及迟到响应隔离。
10. 单个请求取消不影响连接。
11. 服务错误字符串脱敏。
12. 畸形消息和进程退出结束等待。
13. 意外服务器请求拒绝及自有进程清理。
14. 缺失可执行文件返回明确错误。

测试使用受控的虚构子进程协议。它们验证本模块的处理逻辑，不代替真实断网、服务限流、额度重置或跨设备测试。
