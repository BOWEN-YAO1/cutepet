# 天依动作增强（0.9.1）

2026-10-02。保留小猫和天依原有四张素材，天依保留五张新增透明 PNG：左右看、开心笑脸、抬手中间姿势及向外摆手。0.9.1 按反馈撤掉歪头动作和 tilt-v2.png，悬停时保持正常站姿。动作仍放在天依自己的角色包中，公共播放器只处理触发、优先级和生命周期。

## 怎么体验

先退出旧桌宠，再解压 0.9.1 便携包，双击 CutePet.exe。右键或托盘 → 角色选择 → 洛天依（同人）；原来的位置、角色选择和显示设置继续使用。

| 场景 | 动作 |
|---|---|
| 正常待机、鼠标未悬停角色 | 每隔随机 8–16 秒尝试左右张望，持续约 1.14 秒 |
| 鼠标停在角色上 | 保持站姿；额度详情仍按原悬停设置展开 |
| 点击角色 | 随机多姿态挥手或开心笑脸；挥手约 1.12 秒，开心 0.9 秒 |
| 正常待机 | 保留每 4 秒一次、持续 160 毫秒的眨眼和轻微浮动 |
| 有效、新鲜的额度低于 20% | 保留疲惫表情，暂停自动张望；点击后回到疲惫状态 |

天依没有悬停姿势动作。位置锁定后点击和悬停仍可用；拖动、按住左键或打开右键菜单时不触发新的自动动作。点击优先于张望或眨眼；快速重复点击重新播放，不积压动作队列。隐藏时停止计时器并清除临时动作，换角色也会复位。

管理 / 导入角色窗口新增动作下拉框，选择后点击“播放动作”即可单独查看。低额度预览不需要真实账号，预览本身不消耗 Codex 额度。

## 角色包如何扩展

formatVersion 仍为 1；公共格式支持 look、hover、happy 三个可选有限动作，内置天依仅使用 look 和 happy；hover 继续留给自定义角色，均要求 loop: false，帧时间由角色包控制。0.8 的四动作包和静态 PNG 继续可用，缺少动作时不自动生成姿势。带新动作的包需要 0.9.0 或更新程序，0.8 不支持这些动作名称。

素材和配置在 src/CutePet.Desktop/Characters/Packs/tianyi/，触发与计时在 Views/Controllers/CharacterPresenter.cs，播放优先级在 Characters/CharacterAnimation.cs。下一步补动作时可以先加 PNG 和 character.json；需要新的触发类别时再扩展公共播放器。

当前九张图均为 1024×1535 透明 PNG，加载时缓存并冻结；重复引用不重复解码，总解码像素 14,146,560，继续满足已有上限。生成过程使用内置 image_gen.imagegen 编辑模式；完整提示词保留在天依包 SOURCE.md / PROMPTS.md，含已撤掉动作的历史生成记录。素材为非官方同人，权利说明见仓库 THIRD_PARTY_NOTICES.md。

## 验证与验收

自动检查覆盖全部独立素材的透明度、画布尺寸和缓存，新动作优先级、点击重启、低额度转换、静态包 / 旧包兼容、新包导入导出、天依悬停保持站姿、自定义悬停动作兼容、菜单暂停、隐藏与换角色复位，以及真实 WPF 计时器结束动作。验证使用隔离目录、模拟额度和离屏窗口，不修改个人设置或开机启动项。

人工试用：选择天依后等待至少 16 秒；悬停角色，离开再进入；连续点击；锁定位置再悬停和点击；隐藏后恢复并切换小猫；在角色管理中预览六种动作。观察脚底是否稳定、发饰和手臂切换是否突兀，以及菜单和拖动是否被动画打扰。

这是逐帧动画，仍能看到姿势切换，尚未实现骨骼动画或连续补间。自动检查与离屏截图不能替代实际桌面上的动画观感验收。
