# 连续姿势图集（0.38.0）

0.37.0 调整了活动等待、收云和整体运动，但人物多数动作仍只在少数姿势间切换。0.38.0 直接补绘人物过程帧，继续使用角色包播放器；小猫及既有自定义包保留原动作。

本版天依有 28 个动作、240 次帧引用、96 个不同姿势。六张图集各含 16 个姿势：

| 图集 | 动作过程 |
| --- | --- |
| standing-sequence-v4.png | 半闭眼与闭眼、抬手与转腕、开心表情、左右张望 |
| throne-sequence-v4.png | 施法、王座成形、落座、坐姿眨眼和挥手 |
| cloud-sequence-v5.png | 疲惫表情、随风发丝与裙摆、乘云眨眼、召云 |
| edge-sequence-v5.png | 八级渐进探出、回收、点头、害羞和张望 |
| bottom-sequence-v6.png | 托腮抬头、半闭眼与微笑、转头和歪头 |
| top-sequence-v4.png | 秋千坐姿、眨眼、张望和微笑 |

左右、下侧、上侧都从八个不同姿势增加到十六个。挥手先抬手，再转腕，最后经过中间帧放下；坐姿回应也采用有限过程帧。普通过程帧以 80–160 毫秒为主，快速眨眼使用 40–80 毫秒，待机和表情顶点保留适当停留。坐下约 1.5 秒，起身约 1 秒；过程中唤醒使用同区域逆序，保留当前姿势。此处的 96 是全包不同姿势总数，不是每个动作有 96 帧，也不是屏幕帧率。

乘云增加可选循环 `cloud-idle` 与有限 `cloud-blink`。云朵完全出现后才切入随风姿势，眨眼后继续循环；菜单、悬停和详情仍暂停运动。收云、锁定、隐藏、换角色和低额度会清理乘云姿势。额度条独立，不随人物移动。角色管理的动作列表可预览这两个新动作及云层。

## 素材登记与资源预算

原始 PNG 原样复制，透明 alpha 保留。AI 排版的行距不完全等分，配置因此使用实际 `region`：普通姿势 240×360、贴边 256×352。运行时使用冻结的 CroppedBitmap，同区域跨动作共享缓存。左右扶边逐帧登记 X/Y，下沿袖底对齐支撑线，上侧两根绳底对齐玉座，悬挂点到坐板保持同一距离。

本版活跃 PNG 从 26 张归并为 9 张：六张图集与三张已有装饰图。原图 14,155,078 像素，96 个区域 8,472,576 像素，保守合计 22,627,654 像素，约 86.32 MiB BGRA；上一版为 45,591,878 像素。175 MiB 的解码预算不变。数值是素材预算，不代表程序全部内存。编译资源和角色导出只包含活跃图片；历史姿势图与来源记录留在源码。

`tools/register-tianyi-sequences.py` 读取图集、生成取帧与接触点配置，不修改图片。维护者复现需要 Pillow；普通运行、构建和打包不需要。用 `--check` 可检查已保存配置。

角色格式仍为 1，旧包与单 PNG 导入继续工作。新包需 0.38.0：动作引用上限调整为 384，配置为 128 KiB；PNG 的 8 MiB / 2048 边长、说明文件 64 KiB、单动作 30 秒、ZIP / 解压 64 MiB、总解码预算保持。新配置约 70 KiB，不能用较旧应用导入。

## 验证与体验

隔离验证检查 96 个不同像素哈希、冻结缓存、上下透明留白、乘云循环与复位、逐帧支撑线、坐板连接、原四动作小猫、单 PNG / ZIP 导入导出、引用和配置边界。预览来自角色包播放器与实际 WPF 窗口，不连接账号，不改动真实设置。

`previews/animations/pose-sequences.gif` 对照挥手、开心、召唤、坐姿挥手与乘云；另有王座、坐姿、左右 / 上侧 / 下侧动作及收云 GIF。

退出旧版、完整解压新版，选择内置天依体验；旧导入角色不会被覆盖，可另行导入新版角色 ZIP。请重点体验抬手、回收、乘云发丝、逐渐探头以及上 / 下支撑点。AI 帧间的发丝、衣纹和椅饰仍会有轻微变化，当前不是骨骼动画，不能保证与逐帧手绘同等连续。
