# 上侧秋千连续动画（0.47.0）

本版将内置天依上侧动作迁移到与左右侧边共用的原生动画渲染器。上侧共用一张固定人物底图和一个闭眼图层文件，采用时间曲线驱动闭眼点头、左右张望、歪头；下侧、乘云、站立与王座仍沿用现有序列方式。

## 动画结构

NativeAnimationView 使用WPF保留模式网格。上侧32列、72行，共2409个人物顶点、4608个三角形；眼部另外两个四顶点矩形。头部影响在玉座上方归零，座椅与两端绳索连接区域始终固定。眼睛局部渐进压缩，闭眼画面只裁取两个眼部区域，边缘3像素柔化，并随头部运动。文件仍为原登记PNG，裁切和柔化发生在运行时。

闭眼程度采用三次Hermite曲线，0表示睁眼，1表示闭眼；其他位移与角度也按同一连续曲线计算，不轮换整张人物图。动作起止值和速度均回到零，反复点击不排队。绳索、秋千整体轻摆、花藤和挂饰沿用原控制器，额度仍在独立窗口。

顶点集合双缓冲，修改前暂时从场景分离，底图材质冻结；眼部描绘和渐变遮罩也冻结，仅图层透明度变化。没有更新姿势时不重复重建网格。切换到侧边恢复既有325顶点网格，切换到旧角色清理原生场景。共享渲染器名称由SideAnimationView改为NativeAnimationView。

主界面角色页复用NativeAnimationPreviewRenderer的小尺寸144×192透明表面，上限30fps；实际桌宠直接绘制原生网格，随屏幕刷新采样实际时间。动画层在隐藏期间先按绑定的图片尺寸适配相机，并在每次呈现时校正，避免复用侧边窗口后首次上侧画面突然放大。GIF是25fps预览，窗口行为验证仍每20毫秒检查；不把导出GIF用作程序动画资源。

## 角色包格式

可选 `topAnimation` 包含：

- `headPivotX/Y`：头部旋转支点，比例坐标；x为0.3–0.7，y为0.35–0.55，且须位于座椅上方至少0.12。
- `closedEyesImage`：同画布的本地闭眼PNG，使用既有图片路径安全和解码预算限制。
- `eyes`：依次排列的两个不重叠眼部矩形，使用像素坐标；必须位于画布上半部，每眼8像素以上、宽不超过画布25%、高不超过15%。
- `clips`：已有上侧回应的2–32个控制点，`at`严格递增覆盖0–1；`peek`为横向位移（−8至8像素）、`lift`为上下位移（−5至5像素）、`angle`为旋转（−5至5度）、`sway`为发梢与腿部轻摆（−3至3）、`blink`为闭眼程度（0至1）。首尾全部运动为0。

上侧所有动作必须只有一帧，共用同一个登记底图、座椅、悬挂点与头部锚点，并关闭smoothFrames。缺少曲线、混合姿势图、非有限值、错误闭眼图、越界或重叠眼部区域都会被拒绝。sideAnimation中的blink必须保持0。字段缺失的旧包继续用原序列播放器；新天依包需要0.47.0。

该试验模型需要与现有登记姿势一致的底图与眼部区域，不能自动适配任意立绘；尚未拆分完整发丝、手臂、嘴型与服装骨骼。

## 验证与限制

`--verify-top-animation <目录>` 验证真实透明绘制、闭眼效果、固定座椅区域、60Hz网格采样无折叠、起止像素一致、纹理稳定和角色切换。`--verify-top-window <目录>` 单独检查实际秋千动作、悬挂点与花藤；`--verify` 额外检查真实秋千绳索连接、菜单暂停网格与眼部像素、快速点击、工作区域变化、主界面预览及角色包导入导出。

本机专门验证27项通过：睁眼区域117个绿色虹膜像素在闭眼后为0，60Hz相邻网格顶点最大移动约0.854源像素。该结果验证连续变形与可见闭眼，不代表所有电脑都能恒定60fps。实际帧率还受WPF合成、显示器、设备和透明窗口影响。
